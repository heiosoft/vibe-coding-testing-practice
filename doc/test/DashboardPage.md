## [x] 【前端元素與初始渲染】畫面初始載入時應顯示載入中狀態
**範例輸入**：元件剛掛載，API 尚未回傳
**期待輸出**：畫面顯示「載入商品中...」及 Loading Spinner。

---

## [x] 【用戶資訊呈現】應正確顯示使用者的名稱與頭像首字母
**範例輸入**：AuthContext 提供 `user: { username: 'TestUser' }`
**期待輸出**：畫面顯示「Welcome, TestUser 👋」，且頭像顯示大寫首字母「T」。

---

## [x] 【用戶資訊呈現】當角色為 admin 時應顯示管理後台連結與管理員標籤
**範例輸入**：AuthContext 提供 `user: { role: 'admin' }`
**期待輸出**：畫面顯示「🛠️ 管理後台」的連結，以及「管理員」的標籤。

---

## [x] 【用戶資訊呈現】當角色為一般用戶時不應顯示管理後台連結
**範例輸入**：AuthContext 提供 `user: { role: 'user' }`
**期待輸出**：畫面上「不會」出現「🛠️ 管理後台」的連結，且顯示「一般用戶」的標籤。

---

## [x] 【Mock API 與 商品列表】API 請求成功時應隱藏載入狀態並渲染商品
**範例輸入**：Mock `productApi.getProducts` 成功回傳包含 2 個商品的陣列
**期待輸出**：載入狀態消失，畫面上出現這 2 個商品的名稱、描述與價格。

---

## [x] 【Mock API 與 商品列表】API 請求失敗時 (非401) 應顯示錯誤訊息
**範例輸入**：Mock `productApi.getProducts` 回傳 500 錯誤及訊息「伺服器錯誤」
**期待輸出**：畫面隱藏載入狀態，並顯示錯誤區塊與訊息「伺服器錯誤」。

---

## [x] 【Mock API 與 商品列表】API 請求發生 401 錯誤時不應顯示錯誤訊息
**範例輸入**：Mock `productApi.getProducts` 回傳 401 錯誤
**期待輸出**：元件 catch 到 401 錯誤時會直接 return，因此不會設定 error 狀態 (錯誤訊息維持 null，畫面顯示空白商品區或預設狀態，因為交由 axios interceptor 處理登出)。

---

## [x] 【互動邏輯】點擊登出按鈕時應呼叫 logout 並導向 login 頁面
**範例輸入**：點擊「登出」按鈕
**期待輸出**：成功觸發 `logout()` 函數，並且呼叫 `navigate('/login', { replace: true, state: null })`。
